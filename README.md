# FoodBridge

A smart food donation and poverty-support platform for Egypt. FoodBridge connects restaurants, bakeries and supermarkets with verified families and volunteer drivers so surplus food reaches people who need it before it expires — in service of UN SDG 1 (No Poverty) and SDG 2 (Zero Hunger).

Live site: https://foodbridge.site.accio.ai

## Stack

| Layer | Choice |
|-------|--------|
| UI | React 18 + TypeScript, React Router 6 |
| Styling | Tailwind CSS 3 with a CSS-variable token layer |
| Backend | Supabase — PostgreSQL, Auth, Storage |
| Charts | Hand-authored SVG (no chart dependency) |
| Languages | English + Arabic with full RTL |

## Features

- **Four roles** — donor, beneficiary, volunteer, administrator — each with its own dashboard and permissions.
- **Donation lifecycle** — post surplus food with a photo, administrator approval, matching, delivery, completion.
- **Assistance requests** — household size, urgency, category, cancellation, status tracking.
- **Rule-based matching engine** — weighted score over category, quantity, expiry, location and urgency. No AI, no paid API.
- **Delivery workflow** — open task board, volunteer claim, three-step status progression with automatic cascade on completion.
- **Notifications** — generated by database triggers, never by the browser.
- **Impact analytics** — live KPIs, six-month trend, category breakdown, urgency mix, CSV export.
- **Bilingual UI** — English and Arabic, chosen in Settings, persisted per user, `?lang=ar` for share links.
- **Egypt coverage** — all 27 governorates, displayed in the active language.

## Getting started

```bash
npm install
cp .env.example .env      # then fill in your Supabase project values
npm run dev
```

Production build:

```bash
npm run build             # outputs to dist/
npm run preview
```

## Supabase setup

1. Create a Supabase project.
2. Apply `supabase/migrations/0001 … 0010` in order. They create the schema, row-level security policies, guard triggers, reporting functions, notification triggers and the `donation-images` storage bucket.
3. Run `0005_seed_accounts` and `0006_seed_data` to load demo accounts and sample data (optional).

Only the **anon** key belongs in the frontend. The `service_role` key must never be committed or shipped to a browser.

## Security model

Row-level security is enabled on every table. Routes are guarded in React, actions are hidden in the UI, and PostgreSQL rejects unauthorised queries independently — so a tampered client cannot escalate. Owners cannot change their own role or verification status, donors cannot approve their own donations, and volunteers can only progress their own assignments.

Passwords are managed by Supabase Auth and stored as bcrypt hashes; no plaintext or hash exists in this schema.
